# ESP-SparkBot 与顶部触摸对话版

本目录保留 `esp-sparkbot` 原版，并新增 `esp-sparkbot-touch` 构建变体。后者面向本地 ESP-SparkBot 实物：ESP32-S3、16MB Flash、8MB PSRAM、ES8311、240×240 ST7789 屏幕。摄像头和底盘 MCP 接口继续沿用上游。

## 顶部触摸操作

| 当前状态 | 轻触顶部一次 |
| --- | --- |
| 待机 | 先说“您好，找我有什么事情吗？”，完整播完后连接会话并开始聆听 |
| 正在连接 | 取消会话并播放告别语；连接握手中的取消会在握手返回后生效 |
| 正在聆听、等待回答或播报 | 停止收音和云端会话，再说“再见啊，下次有需求可以再来找我”，播完回到待机 |
| 正在播放服务端通知 | 停止通知，回到待机 |
| 启动、配网、激活、升级 | 忽略触摸 |

停止会清除本地待播音频和发送队列，并阻止已停止会话的迟到 TTS 再次开启播放。停止不会删除服务端聊天历史，也不会禁用本地唤醒词；之后仍可重新语音唤醒或轻触开始。

手指保持接触只触发一次，必须松开再触碰。输入每 20ms 采样，连续 3 次稳定变化确认按下或松开，另有 400ms 防重复间隔。无需外接 TTP223。

两句提示语在本地播放，不需要联网生成。问候和告别期间不收音、不运行唤醒词检测。问候中再次轻触会取消开始对话并播放告别语；告别期间的额外触摸被忽略，播完即可再次触摸开始。声音采用 Microsoft Huihui 简体中文音色，句子按用户指定原文固定播放。

提示音以有界队列分段送入解码器，不等待队列空位；只有最后一帧和输出尾音都播放结束，才允许进入聆听。语音唤醒和原 BOOT 按钮仍沿用原有提示方式。

## 引脚与兼容处理

- 顶部为原 BSP 的确认按键：触摸通道 1 / GPIO1。原出厂工程中 `case 1` 对应确认，2、3 对应侧面切换。顶部左右两块电极连在同一通道。
- 默认相对阈值为基线的 3.5%，沿用本地 BSP 的顶部灵敏度起点。可在 `menuconfig` 调整通道与阈值；实际灵敏度仍需在外壳装好后测试。
- 采用 ESP-IDF 6 的 `esp_driver_touch_sens`，没有继续使用旧版 `touch_pad` / `touch_element`。上电标定期间不要触碰电极。
- 触摸版屏幕 SPI 使用昨天本地工程采用的 20MHz。
- GPIO46 是屏幕背光。触摸版给 ES8311 传入 `GPIO_NUM_NC` 作为 PA 控制脚，避免开关音频时改动背光；音频输入、输出继续共用原有 ES8311 全双工设备。
- 原版 `esp-sparkbot` 保持原有引脚配置与按钮语义，顶部触摸处理源码不会参与其构建。底层触摸组件按 S3 目标声明依赖，以兼容 ESP-IDF 在加载配置前进行的依赖扫描。

## 编译

上游最低要求 ESP-IDF 6.0.1，建议使用 `release/v6.1` 分支。昨天工程的 ESP-IDF 5.2.3 环境不能直接用于当前上游，请使用独立的新环境。

在已导出的 ESP-IDF 6 环境中，于仓库根目录执行：

```sh
python scripts/build.py espressif/esp-sparkbot --name esp-sparkbot-touch --language zh-CN --zip
```

也可通过 GitHub Actions 的 `Validate SparkBot touch` 工作流编译原版、触摸版，成功后下载对应固件 artifact。编译成功只说明软件构建通过，仍需实物验证麦克风、扬声器、屏幕、触摸和联网。

2026-10-24 原版、带问候/告别语的触摸版、代表性 ESP32-C3 固件及 149 项主机测试均已通过，详见 [验证记录](../../../../docs/sparkbot-touch-validation.zh-CN.md)。

## 天气与语音服务

本次增加触摸交互入口；天气查询继续由所接服务端或 MCP 工具提供。没有把天气网页抓取、API Key 或昨天工程的私有配置写入固件仓库。详细比较见 [语音与天气实现研究](../../../../docs/sparkbot-touch-research.zh-CN.md)。

## 实物验收

1. 上电不触碰顶部，确认启动成功、屏幕正常、服务端激活完成。
2. 轻触开始，确认完整听到“您好，找我有什么事情吗？”后才开始聆听；询问普通问题，确认收音、识别和播报。
3. 分别在连接、聆听、等待回答、播报时再触碰，确认停止会话、完整说出“再见啊，下次有需求可以再来找我”后回到待机；随后等待，确认迟到回答不会再次播放。
4. 长按顶部确认只触发一次；松开后再触碰，确认可再次启动。
5. 验证原有语音唤醒、BOOT、摄像头和底盘功能。
6. 后端接好真实天气工具后，询问默认城市、指定城市及网络失败场景。检查城市和更新时间，不能把模型自由生成的天气当作查询结果。

本地实物已按用户授权更新程序分区，保留配网和激活信息。昨天工程与原固件备份仍在各自目录；换另一台设备前须核对分区和备份。
